- **DEX** → hedge is **already on**. Read it as where customers lean.
- **Convexity / GEX profile** → hedge is **ahead**, if spot moves.
- Only the second is “forced flow ahead.” The first is a record.

“DEX bar = pending buying” is the second import mistake on this page. “Long bar = support” is the first.

## Options profile

<GexbotConcept id="options-profile" />
<WhoMustAct screenId="state-op" />

Significant strikes are liquidity concentrations — “stops on the roadmap” (*docs*). Direction comes from incentives, not from the bar existing.

Falling-vol tape (*folklore*): customer **longs** act like walls (dump, supply liquidity); customer **shorts** act like fuel (hedge/add, take liquidity). Rising vol **flips** both. If you cannot tell the regime, the OP read is off.

## Running example

**Bought 500 ATM calls.** OP long-call bar **right**; DEX **+**; convexity **+** at the strike. Customer incentivized (theta, falling vol) to sell on approach (*folklore*). Dealer mandated to **chase** if spot rips (pending gamma).

**Sold 500 ATM calls.** OP short-call bar **left**; DEX **−**; convexity **−**. Customer incentivized to sit / defend. Dealer mandated to **fade**.

DEX is the record of the ~500 ES already done. Convexity is the ~300 ES that appear only if spot walks +15.

## Summary

State shows leftover paper by strike. Read the orientation card before the color. DEX is already hedged; convexity is pending and path-conditional.

## Newcomer questions

1. **Long bar = support?** Only as a falling-vol *incentive* hypothesis (*folklore*). Rising vol can make that long into fuel.
2. **DEX printed + — will they buy ES?** Inferred initial hedge is mostly done. Pending force is on gamma.
3. **Is GEX profile the same as convexity?** No. Wing (call vs put) vs ownership (paid vs collected).
